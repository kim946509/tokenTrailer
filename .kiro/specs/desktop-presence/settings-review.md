# 기본 설정 검토안

수정일: 2026-10-20. 사용자는 AICap처럼 한도 갱신 주기를 선택하도록 요청했다. 아래는 [AICap 설정 분석](../../../docs/research/aicap/settings-workflows-report.md)과 [프로필별 주기 근거](../../../docs/research/aicap/providers-analysis.md)를 기준으로 제품 목적에 맞는 설정을 구분한 목록이다. AICap 개인 설정 파일을 가져오거나 변경하지 않는다.

## 우선 반영

| 설정 | 동작/초기안 | 상태·이유 |
|---|---|---|
| 한도 자동 갱신 주기 | 5초·15초·30초·1분·5분 선택, 기본 5분 제안 | 선택 기능은 사용자 승인. 구체 선택지/기본값은 AICap 선례 적용안 |
| 주기 적용 단위 | 연결별 선택, 새 연결은 기본 5분 제안 | AICap 프로필별 주기 참고. 다른 도구의 rate limit과 독립 운용 |
| 수동 갱신 | 즉시 요청하되 진행 중 요청 통합, 서버 대기 제한 준수 | 반복 클릭으로 중복 요청하지 않음 |
| 서버 제한 상태 | Retry-After 동안 대기, 다음 시도 시각 표시 | 사용자가 5초를 선택해도 서버 제한을 무시하지 않음 |
| 자동 시작 / 시작 시 창 숨김 | 독립 옵션. 자동 시작은 최초 설정에서 선택 | AICap의 두 설정 구분 참고. 원래 미정인 시작 창 기본값은 검토 유지 |
| 위젯 표시 / 항상 위 / 위치 복원 | 독립 옵션, 모니터 이탈 시 화면 안 복귀 | 기존 요구사항. 표시 실패 때문에 저장된 켜짐 설정을 끄지 않음 |
| 표시할 도구·연결 | 작업표시줄·위젯에서 대상 선택 | AICap 프로필 고정 참고. 여러 계정 관리 범위까지 자동 확대하지 않음 |

짧은 주기를 선택하는 설정 화면에서 요청 제한 가능성과 5분 기본안을 간단히 안내한다. 팝업을 매번 띄우지 않는다. 위젯의 남은 시간/로컬 캐시 갱신과 실제 외부 요청은 분리한다. 기본 5분에서 5초로 변경하면 현재 진행 요청은 중복 실행하지 않고 다음 허용 요청을 새 주기로 예약한다. 5초에서 5분으로 변경하면 오래된 짧은 주기 타이머를 취소한다. 절전 복귀 후 누락된 주기 수만큼 몰아서 요청하지 않는다.

## 참고 가능한 추가 기본 설정 — 아직 제안

| 설정 | 제안 | 검토 이유 |
|---|---|---|
| 사용률 / 남은 비율 | 사용률 기본, 남은 비율 선택 제공 | AICap 반전 표시 참고. 단위/문구도 함께 변경 |
| 시간 표시 | PC 시간대, 24시간 표시 기본 제안 | reset 절대시각과 남은 시간을 명확하게 표시 |
| 테마 | 시스템 따르기 기본, 밝음/어두움 | AICap 참고 가능한 기본 UI 설정. 첫 버전 필수 여부는 검토 |
| 모니터 선택 | 기본 주 모니터, 별도 선택은 후속 검토 | 멀티 모니터 표시 공간·DPI 검증 필요 |
| 로컬 토큰 수집 주기 | 기본 30초 제안 | 한도 API 주기와 다른 설정이며 AICap 값을 그대로 적용하지 않음 |
| 기간·주 시작 | 오늘/이번 주/이번 달, 월요일 | 토큰 그래프의 제품 고유 기본값 |
| 토큰 합계 | 캐시·추론 중복 없이 포함 | 도구별 포함 관계 검증 후 적용. 캐시를 입력 위에 다시 더하지 않음 |
| 창 닫기 | 상주 유지, 명시적 종료 별도 | 기존 제안 유지 |
| 이력 삭제 | 원본 불변, 과거 자동 재수입 방지 | 전체 수집·보존·삭제 가능은 승인. 삭제 제외정보 상세는 검토 |

## 자동으로 가져오지 않는 기능

계정 전환·인증정보 내보내기·백업/Drive·자동 채팅으로 사용 창 시작·리셋 크레딧 소비·업데이트 설치는 기본 표시/갱신 설정과 구분한다. 현재 목표에 따라 별도 요청 없이는 포함하지 않는다. 다국어·투명도·막대 크기 등 장식 옵션도 첫 검증 단계의 필수로 늘리지 않는다.

기존 설정 저장 실패, 손상, 키보드 변경 저장, 여러 창 간 설정 일치 요구사항은 유지한다. AICap의 낙관적 저장 실패를 로그만 남기는 방식은 그대로 가져오지 않는다.
