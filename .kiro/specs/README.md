# TokenTrailer 상세 요구사항 검토

2026-10-20 후속: 사용자의 MVP까지 구현·시험 진행 승인으로 [MVP 설계](../../docs/MVP_DESIGN.md)에 따라 앱을 구현 중이다. Electron·로컬 JSON 저장·Win32 보조 프로세스를 이번 MVP 선택으로 사용한다. 기본값은 설계 문서에 기록하고 설정으로 변경할 수 있게 한다. 실제 Gemini 조회와 Windows 복구 조합은 출시 미검증 조건으로 유지한다. 아래 과거 제안 상태가 구현 완료나 출시 승인으로 자동 변경되는 것은 아니다.

상태: 사용자 검토용 초안 · 2026-10-19 / 갱신 2026-10-20. 아래 승인 범위와 제안 기본값을 구분한다. 승인된 범위의 실행 검증과 Gemini 독립 한도 모듈 구현을 진행했다. [구현 작업 현황](account-quota/tasks.md) 참조. 전체 앱과 실제 Gemini 조회는 미완료다.

상위 문서: [전체 기능명세](../../docs/FUNCTIONAL_SPEC.md), [프로젝트 목표](../../docs/PROJECT_GOALS.md). 각 문서의 UC/UA/DP/AQ 번호는 요구사항 ID이며 소수점 번호는 개별 수용 기준이다. WHEN은 사건, WHILE은 상태, IF/THEN은 예외 조건을 나타낸다. 수용 기준은 검증해야 할 목표이며 구현된 사실이 아니다.

제공자별 수집 방식 설계 요청에 따라 [계정 한도 설계안](account-quota/design.md)과 [로컬 토큰 수집 설계안](usage-collection/design.md)을 작성했다. 미결 요구사항을 승인 처리하지 않은 검토용 설계이며, 전체 화면·저장·작업 계획 설계 완료를 의미하지 않는다.

## 승인된 범위

- Windows 11. Claude Code, Codex CLI·데스크톱, Gemini CLI가 최소 필수다. Codex 데스크톱도 실제 로컬 기록을 검증한 범위를 명시해야 한다.
- 작업표시줄에 클릭 없이 수치 직접 표시와 별도 미니 위젯이 필수다. 트레이만으로 대체하지 않는다.
- 필수 3개 도구 모두 계정 요금제의 실제 한도 사용률과 초기화 정보를 조회해야 출시할 수 있다. 도구별 지원 계정·요금제 범위는 아직 확정하지 않았다.
- 최신 사용자 설명에 따라 금액보다 계정 한도 대비 사용률을 우선한다. API 단가 환산·실제 청구 금액은 첫 버전 필수에서 제외한다. 구독료를 토큰 단가나 사용률 분모로 환산하지 않는다.
- 발견한 지원 기록 전체를 수집하고 원본 삭제 후에도 앱의 사용량 이력을 유지한다. 앱 이력 삭제 기능을 제공한다.
- Kimi CLI/Code·Grok Build는 추가 목표, PC 귀속·여러 PC 비율·자동 작업 분류는 후속이다.

D-04~D-08의 세부 기본값 제안과 이후 MVP 구현값은 개별 설계에 기록한다. D-10·D-11은 승인되었다. 사용자는 Claude·Codex를 사용하고 Gemini는 사용하지 않으며, 이 개인 사용 현황은 제품의 지원 요금제를 제한하지 않는다. 제공자·로그인 방식·계정 유형별 지원과 시험 가능 환경을 분리한다. 2026-10-20 추가 요청에 따라 연결된 AI 필터와 프로젝트별 AI 토큰 구분을 사용량 분석에 포함한다.

2026-10-20 승인에 따라 Codex 데스크톱 및 Windows 작업표시줄 기술 검증을 진행했다. [초기 검증](../../docs/research/validation/2026-10-20-feasibility.md)에서 일반 자식 창 숫자가 미표시됐으며, [후속 원인 분석·1~5단계 결과](../../docs/research/validation/2026-10-20-taskbar-followup.md)에서 layered 시험 창의 직접 표시와 모의 복구를 확인했다. 실제 셸/로그인 복구·제품 배치 검증은 남아 있다. Claude 한도 실조회와 Codex 수치 감사, Gemini 참고 구현 fixture 검증도 후속 보고서에 구분했다. 기본 설정은 [설정 검토안](desktop-presence/settings-review.md)에 정리했다.

## 공통 품질·출시 검증

| 검증 ID | 통과 조건 |
|---|---|
| V-01 | 필수 클라이언트별 버전·형식이 명시된 비식별/합성 기준 자료에서 토큰 값, 캐시·추론 포함 관계, 반복 수집 결과가 기대값과 일치 |
| V-02 | 동일 조회 조건·동일 데이터 시점에서 요약/그래프/프로젝트/세션/상주 수치 일치. 부분·미귀속을 설명 |
| V-03 | 필수 3개 도구 각각 승인된 요금제의 실제 계정에서 한도·초기화 조회 성공. 모의 응답만으로 지원 완료 판정 금지 |
| V-04 | 실제 Windows 로그인, Explorer 재시작, 절전 복귀, 모니터·배율 변경 시 직접 표시와 위젯 접근 가능. 프로세스 존재만으로 성공 판정 금지 |
| V-05 | 실패·미지원·빈 기록·실측 0 구별, 설정 저장 실패 표시, 원본 로그·설정·인증 파일 불변, 비밀정보 로그 미포함 |
| V-06 | 승인된 기본값·성능 목표로 아래 시나리오 검증. 미승인 또는 미검증 항목이 있으면 완료로 표시하지 않음 |

성능 검토안: Windows 11, 4코어 이상·RAM 16GB·SSD의 명시된 시험 PC에서 10만 이벤트/최대 1GB 입력을 사용한다. 최초 수집 60초 이내, 최초 진행 상태 1초 이내, 수집 중 필터·메뉴 응답 p95 500ms 이내, 수집 후 조회 p95 1초 이내를 제안한다. 신규 100이벤트는 원본 기록 완료 후 35초 이내 표시한다. 측정은 최소 20회 상호작용으로 하며 데이터·하드웨어·앱 버전을 기록한다. 원본 작성 지연은 별도로 측정한다.

복구 검토안: OS 셸 사용 가능 후 30초 이내 직접 표시 복구, 데이터 수집 대기 없이 표면 표시. 초기 수집을 제외한 유휴 10분 동안 프로세스 트리 평균 CPU 1% 이하·메모리 250MB 이하를 목표로 제안한다. 네트워크 서비스 지연·rate limit은 한도 최신성 보장과 분리하여 표시한다. 이 수치는 실측 결과가 아니다.

검토 순서: 사용자 결정 및 기본값 검토 → 지원 형식·요금제와 한도 연결 가능성 확인 → 요구사항 확정 → design.md → tasks.md. 한도 확보나 직접 표시가 불가능하면 근거와 대안을 보고하고 범위 변경 검토를 받으며 임의로 완료 기준을 낮추지 않는다.
