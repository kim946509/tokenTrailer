# 사용량 분석 상세 요구사항

상태: 검토용 초안 · 2026-10-19. [결정 목록](../README.md), [공통 토큰 계약](../usage-collection/requirements.md)을 따른다. F-05~F-08을 담당한다.

## UA-01. 요약과 조회 범위

사용자 스토리: 사용자는 선택 기간에 얼마나 사용했는지 도구별로 비교하고 싶다.

- UA-01.1 WHEN 대시보드를 열면, 시스템은 선택 기간·시간대·도구, 토큰 합계와 구성, 출처 상태 및 마지막 성공 시각을 표시해야 한다. 기본 오늘·OS 시간대는 D-05 제안이다.
- UA-01.2 WHEN 기간 또는 도구를 변경하면, 시스템은 요약·그래프·프로젝트·세션에 동일 조건을 적용해야 한다. 선택지는 오늘/이번 주/이번 달과 전체 기록/연결된 AI 전체/개별 AI를 제공해야 한다. 연결이 해제된 AI의 보존 기록도 개별 조회할 수 있어야 한다(2026-10-20 사용자 추가 승인).
- UA-01.5 WHEN 기간·구간의 사용량을 표시하면, 시스템은 AI별 로컬 토큰 합계 및 표시 합계 대비 비율을 제공해야 한다. 이를 요금제 한도나 현재 로그인 계정의 사용량으로 표현하지 않아야 한다. 기간 기록 부재를 실측 0으로 표시하지 않아야 한다.
- UA-03.5 WHEN 프로젝트 표를 표시하면, 시스템은 AI별 토큰과 합계를 나란히 제공해야 한다. AI 수치를 선택하면 현재 기간·구간을 유지하며 해당 AI와 프로젝트의 세션으로 좁혀야 한다.
- UA-01.3 WHEN 기간을 계산하면, 시스템은 선택 시간대의 시작 시각 이상·끝 시각 미만으로 처리해야 한다. 이번 주는 월요일 00:00, 이번 달은 1일 00:00 시작을 제안하며 미래 구간을 관측된 0으로 표현하지 않아야 한다.
- UA-01.4 WHEN 날짜 경계를 넘는 세션을 집계하면, 시스템은 확보된 이벤트 시각 기준으로 나누어야 한다. 시각 미확인 기록은 임의 날짜에 배정하지 않고 기간 분석에서 제외된 기록이 있음을 별도 표시해야 한다.
- UA-01.5 IF 일부 도구만 갱신에 성공하면, THEN 시스템은 합계에 포함된 출처·이전값·누락 상태를 설명해야 한다. 수집 기록 합계를 계정 전체 사용량으로 명명하지 않아야 한다.
- UA-01.6 WHEN 계정 한도를 함께 보여주면, 시스템은 토큰 조회 기간과 요금제 한도 창이 다름을 명시하고 두 지표를 서로 환산하지 않아야 한다.

## UA-02. 시간 그래프와 구간 탐색

사용자 스토리: 사용자는 많이 사용한 시간을 찾아 관련 작업으로 이동하고 싶다.

- UA-02.1 WHEN 시간 그래프를 표시하면, 시스템은 축의 토큰 지표·단위·시간대와 구간 경계를 제공해야 한다. 오늘은 시간별, 주간·월간은 일별 막대그래프를 제안한다.
- UA-02.2 WHEN 구간을 선택하면, 시스템은 선택 구간의 토큰 값과 경계를 표시하고 연결된 요약·프로젝트·세션을 그 구간으로 좁혀야 한다. 전체 기간 그래프는 선택 위치를 유지해야 한다.
- UA-02.3 WHEN 구간 선택을 해제하면, 시스템은 원래 기간·도구 필터를 복원해야 한다.
- UA-02.4 IF 시각 정밀도가 일 단위뿐이면, THEN 시스템은 시간 단위로 임의 배분하지 않고 해당 일의 시간 미확인 사용량으로 표시해야 한다. 그래프와 요약 차이를 설명해야 한다.
- UA-02.5 WHEN 비어 있는 구간을 표시하면, 시스템은 수집된 기록 없음과 확인된 갱신 실패/자료 공백을 구별해야 한다. 기록 부재만으로 서비스에서 실제 사용이 없었다고 단정하지 않아야 한다.
- UA-02.6 WHEN 키보드나 보조 기술로 탐색하면, 시스템은 그래프와 동등한 구간 목록·정확한 값·선택 기능을 제공해야 한다. 색상이나 마우스 hover만으로 정보를 전달하지 않아야 한다.
- UA-02.7 WHEN 시간대가 변경되거나 일광절약시간 경계를 조회하면, 시스템은 이벤트의 실제 시각을 보존하여 구간을 재계산하고 반복되는 현지 시각을 구분해야 한다.

## UA-03. 프로젝트 분석

사용자 스토리: 사용자는 같은 기간에 사용량이 많은 프로젝트를 찾고 싶다.

- UA-03.1 WHEN 프로젝트 목록을 표시하면, 시스템은 이름·구분 가능한 작업 공간·도구별 사용량과 합계를 제공해야 한다. 기본 사용량 내림차순을 제안한다.
- UA-03.2 IF 이름은 같고 작업 공간 식별자가 다르면, THEN 시스템은 별개 항목으로 표시해야 한다. 식별자가 없으면 프로젝트 미확인 항목으로 남겨야 한다.
- UA-03.3 WHEN 프로젝트를 선택하면, 시스템은 현재 기간·구간·도구 조건을 유지한 세션 목록을 제공해야 한다.
- UA-03.4 IF 상위 일부만 보여주면, THEN 시스템은 나머지가 있음을 알리고 전체 목록에 접근할 수 있게 해야 한다. 전체 항목과 미확인 항목의 합계는 같은 범위 요약과 일치해야 한다.

## UA-04. 세션 분석

사용자 스토리: 사용자는 실제 실행 세션의 사용량과 시간 분포를 확인하고 싶다.

- UA-04.1 WHEN 세션 목록을 표시하면, 시스템은 확인 가능한 이름 또는 식별자, 도구, 모델, 시각, 선택 범위 기여량과 데이터 상태를 제공해야 한다. 제목을 만들기 위해 대화 원문을 자동 분석하거나 모델에 보내지 않아야 한다.
- UA-04.2 WHEN 상세를 열면, 시스템은 토큰 구성·관련 프로젝트·출처·가능한 시간 분포 및 선택 기여량과 확보된 세션 전체량을 구별하여 표시해야 한다.
- UA-04.3 IF 세션 연결이 불가능한 기록이 있으면, THEN 시스템은 세션 미확인 기여량을 별도로 유지하여 목록에서 사라지지 않게 해야 한다.
- UA-04.4 WHEN 뒤로 이동하면, 시스템은 직전 기간·도구·구간·프로젝트 선택을 복원해야 한다.
- UA-04.5 WHILE 작업을 설명하면, 시스템은 1차에서 프로젝트·세션을 사용해야 하며 근거 없는 버그 수정/문서 작성 등의 자동 분류를 확정 정보처럼 표시하지 않아야 한다.

## 수용 시나리오

| 사례 | 기대 결과 |
|---|---|
| 같은 날 10시 프로젝트 A 100, B 50, 미확인 20; 11시 A 30 | 오늘 200, 10시 선택 170, 해당 프로젝트 합 170, 해제 후 200 |
| 자정 직전 40, 자정 정각 60인 하나의 세션 | 전날 40·당일 60, 확보된 세션 전체 100. 자정 이벤트는 중복 없음 |
| 같은 이름·다른 경로 프로젝트 및 서로 다른 도구의 같은 세션 ID | 각 항목 구분, 합계 불변 |
| 시각 미확인 25와 시각 확인 100 | 기간 분석 100과 시각 미확인 존재를 구별. 임의로 125를 오늘 그래프에 삽입하지 않음 |

검증 연결: V-01, V-02, V-05, V-06. 시간대·기본 기간·지표 제안 승인이 필요하다. 비용 그래프·기기 비율·자동 작업 분류는 이 문서 범위에 포함하지 않는다.

## 2026-10-20 UX 재검토 반영 (최신)
사용자 요청으로 UA-01.2의 전체 기록/연결된 AI 전체 드롭다운을 대체한다. WHEN 사용량을 조회하면, 시스템은 연결된 AI만 전체/개별 AI 버튼으로 그래프 위에 표시하고 동일 조건을 수치·프로젝트·세션에 적용해야 한다. 연결 해제된 AI는 표시/합계에서 제외하되 기록은 보존하며 재연결 후 다시 조회한다. 연동 여부는 설정에서 변경한다. 새로고침 문구를 사용한다.

- UA-01.6 WHEN 큰 토큰 수를 표시하면, 시스템은 K(천)/M(백만)/B(십억)/T(조) 단위와 소수 최대 1자리로 축약해야 한다. 합계·AI별·프로젝트·세션에 동일 규칙을 사용하고 툴팁 및 정확한 구간별 수치 표에서 원값을 제공해야 한다. 집계·저장값은 반올림하지 않는다.
