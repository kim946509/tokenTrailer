# 사용량 수집 상세 요구사항

상태: 검토용 초안 · 2026-10-19. 결정 상태와 기본값은 [검토 목록](../README.md)을 따른다. F-01~F-04, F-20, F-12를 담당한다.

## UC-01. 출처 설정

사용자 스토리: 사용자는 어떤 기록이 수집되는지 확인하고 자신의 클라이언트 기록을 연결하고 싶다.

- UC-01.1 WHEN 최초 설정을 열면, 시스템은 Claude Code·Codex CLI/데스크톱·Gemini CLI별 발견 상태, 기록 위치, 수집할 메타데이터와 지원 범위를 표시해야 한다.
- UC-01.2 WHEN 사용자가 출처를 선택하면, 시스템은 해당 출처를 읽을 수 있는지 확인하고 전체 지원 기록의 초기 수집을 시작해야 한다. 자동 발견 및 수동 경로 지정은 D-02 제안이다.
- UC-01.3 IF 일부 출처가 없거나 접근 불가이면, THEN 시스템은 해당 원인을 표시하고 다른 출처의 설정과 수집을 계속 허용해야 한다.
- UC-01.4 WHILE 초기 수집 중이면, 시스템은 진행 상태와 이미 확보된 부분 데이터를 구분하고 미완료 합계를 최종 합계로 표시하지 않아야 한다.
- UC-01.5 WHEN 수집 범위를 설명하면, 시스템은 로컬에 발견된 기록 기준임을 명시하고 계정 전체 또는 실제 이 PC 발생량이라고 단정하지 않아야 한다.

## UC-02. 필수 클라이언트 파싱

사용자 스토리: 사용자는 필수 도구의 실측 토큰을 모델·프로젝트·세션과 함께 보고 싶다.

- UC-02.1 WHEN 지원 기록을 읽으면, 시스템은 도구, 출처, 가능한 클라이언트 구분, 이벤트 식별 근거, 사용 시각 및 정밀도, 토큰 구성, 모델, 프로젝트, 세션을 확보해야 한다. 없는 선택 정보는 미확인으로 유지해야 한다.
- UC-02.2 IF 필수 토큰 값이 없거나 음수·잘못된 형식이면, THEN 시스템은 임의의 0 또는 문자 수 추정값으로 바꾸지 않고 해당 기록의 불완전 상태를 표시해야 한다.
- UC-02.3 IF 기록 일부가 손상되거나 작성 중이면, THEN 시스템은 정상 기록을 처리하고 제외/보류 범위를 알려야 하며 다음 갱신에서 완성된 기록을 재평가해야 한다.
- UC-02.4 IF 발견된 버전·형식의 의미를 해석할 수 없으면, THEN 시스템은 미지원으로 표시하고 추정 파싱 결과를 확정 합계에 포함하지 않아야 한다.
- UC-02.5 WHEN 지원 완료를 검토하면, 시스템의 검증 자료에는 Claude Code, Codex CLI, Codex 데스크톱, Gemini CLI 각각의 버전·형식·샘플 기대값이 있어야 한다. CLI 검증만으로 데스크톱 검증을 대체하지 않아야 한다.
- UC-02.6 WHILE 사용량을 수집하면, 시스템은 원본 로그·클라이언트 설정·인증 파일을 변경하거나 모델 요청을 발생시키지 않아야 한다. 한도 연결은 별도 AQ 요구사항을 따라야 한다.

## UC-03. 공통 토큰 계약

사용자 스토리: 사용자는 캐시와 추론을 포함해 중복 없는 같은 기준으로 소비량을 비교하고 싶다.

- UC-03.1 WHEN 원시 사용량을 정규화하면, 시스템은 도구·형식별 입력/출력에 캐시·추론이 포함되는지 확인된 매핑을 적용하고 원시값과 해석 근거를 추적 가능하게 해야 한다.
- UC-03.2 WHEN 기본 토큰 합계를 계산하면, 시스템은 상호 배타적인 비캐시 입력 + 캐시 읽기 + 캐시 쓰기 + 일반 출력 + 별도 추론을 합산해야 한다(D-04 제안). 이미 입력/출력에 포함된 구성은 분리하거나 포함 관계를 표시하여 다시 더하지 않아야 한다.
- UC-03.3 IF 전체 입력/출력만 정확하고 세부 구성이 없으면, THEN 시스템은 확인 가능한 전체 합계와 구성 미확인을 함께 표시해야 한다. 구성 미확인만으로 알려진 전체 합계를 잃지 않아야 한다.
- UC-03.4 IF 전체 합계를 확정할 수 없으면, THEN 시스템은 확인 가능한 부분합과 누락 항목을 표시해야 한다. 미확인 값을 0으로 취급하거나 제공자 total과 충돌하는 합계를 정상 전체로 표시하지 않아야 한다.
- UC-03.5 WHEN 분석·상주 화면에서 같은 지표를 조회하면, 시스템은 이 계약을 공통으로 적용해야 한다. 반올림은 표시 단계에만 적용하며 정확한 정수값을 확인할 수 있어야 한다.

합성 수용 예시(특정 버전의 실제 필드 계약을 대신하지 않음):

| 입력 의미 | 기대 총 토큰 |
|---|---:|
| 입력 100에 캐시 읽기 40 포함, 출력 30에 추론 10 포함 | 130 |
| 비캐시 입력 60, 캐시 읽기 40, 캐시 쓰기 20, 일반 출력 30, 별도 추론 10 | 160 |
| 전체 입력 100·출력 30 확인, 캐시/추론 세부 정보 없음 | 130, 구성 미확인 |
| 입력 100 확인, 출력 값 없음 | 부분합 100, 전체 미확정 |

## UC-04. 중복·누적·분기

사용자 스토리: 사용자는 재시작하거나 기록을 다시 읽어도 같은 사용량을 보고 싶다.

- UC-04.1 WHEN 동일 기록을 재수집하거나 앱을 재시작하면, 시스템은 동일 이벤트가 합계에 두 번 반영되지 않게 해야 한다.
- UC-04.2 WHEN 스트리밍 갱신·누적 스냅샷을 읽으면, 시스템은 지원 형식의 최종값 또는 확인된 차분을 사용해야 한다. 누적값 100→150을 독립 사용량 250으로 더하지 않아야 한다.
- UC-04.3 IF 누적값이 감소하거나 기준점이 없으면, THEN 시스템은 음수 사용량이나 임의 차분을 생성하지 않고 형식의 재설정 계약 또는 불완전 상태를 적용해야 한다.
- UC-04.4 WHEN archive·복사·CLI와 데스크톱 공유 기록·분기 세션에 같은 이벤트가 존재하면, 시스템은 확인된 동일성 근거로만 중복 제거해야 한다. 분기의 상속 사용량과 신규 사용량을 구분해야 한다.
- UC-04.5 IF 동일성을 판정할 근거가 부족하면, THEN 시스템은 중복 가능성을 알리고 완전한 중복 제거를 보장하지 않아야 한다. 도구가 다른 같은 세션 ID를 자동 병합하지 않아야 한다.
- UC-04.6 WHEN 검증하면, 동일 자료 3회 수집 및 재시작 후 총량 불변, 누적 100→150의 총량 150, 동일성 확인 복사본 추가의 총량 불변을 확인해야 한다.

## UC-05. 이력 보존·삭제

사용자 스토리: 사용자는 원본 로그가 없어져도 이력을 보고 필요하면 앱 이력을 삭제하고 싶다.

- UC-05.1 WHEN 원본 기록이 삭제·회전되거나 출처 연결이 해제되면, 시스템은 이미 확보한 사용량 메타데이터를 보존하고 마지막 수집 범위를 표시해야 한다.
- UC-05.2 WHEN 사용자가 앱 이력 삭제를 요청하면, 시스템은 삭제 대상(전체 또는 선택 도구), 원본에는 영향이 없다는 점, 재수입 정책을 보여주고 확인 후 처리해야 한다.
- UC-05.3 WHEN 삭제가 성공하면, 시스템은 관련 사용량·프로젝트/세션 메타데이터를 모든 분석과 표시에서 제거해야 한다. 실패 시 완료로 표시하지 않아야 한다.
- UC-05.4 WHEN 삭제 후 자동 수집을 수행하면, 시스템은 삭제 시점까지 이미 처리한 기록을 자동 재수입하지 않고 이후 신규 사용량을 수집해야 한다(D-06 삭제 상세 제안). 이를 위한 최소 제외 식별정보의 보존 범위를 안내해야 한다.
- UC-05.5 WHEN 사용자가 과거 기록 재수입을 명시적으로 선택하면, 시스템은 재수입 범위를 안내한 후 제외된 지원 기록을 다시 수집할 수 있어야 한다(D-06 제안).
- UC-05.6 WHILE 이력을 저장하면, 시스템은 분석에 필요한 사용량·시각·식별 메타데이터만 유지해야 하며 대화 원문과 인증 비밀정보를 앱 이력이나 진단 로그에 복제하지 않아야 한다.

## UC-06. 갱신·상태

사용자 스토리: 사용자는 이전 수치를 최신 수치로 오해하지 않고 실패 후 다시 수집하고 싶다.

- UC-06.1 WHEN 자동 주기 또는 수동 갱신이 발생하면, 시스템은 출처별 수집을 실행하고 같은 출처의 동시 갱신이 중복 반영되지 않도록 해야 한다. 로컬 기본 30초는 D-08 제안이다.
- UC-06.2 WHEN 수집 상태를 표시하면, 시스템은 초기 수집 중/정상/기록 없음/접근 거부/미지원/부분 누락/갱신 실패를 구분하고 출처별 마지막 성공 시각을 제공해야 한다.
- UC-06.3 IF 갱신에 실패하면, THEN 시스템은 이전 성공값을 보존하되 오래된 상태를 표시하고 다른 출처의 갱신을 계속해야 한다. 실패한 출처를 합계에서 조용히 0으로 바꾸지 않아야 한다.
- UC-06.4 WHEN 실패 후 정상 수집이 완료되면, 시스템은 값·성공 시각·상태를 일관되게 갱신해야 한다. 갱신 중인 부분 상태와 완료 스냅샷을 혼합해 화면 간 다른 합계를 정상으로 보여주지 않아야 한다.
- UC-06.5 WHILE 자동 오류가 반복되면, 시스템은 반복 팝업 대신 지속 상태와 원인·수동 재시도 경로를 제공해야 한다.

검증 연결: V-01, V-02, V-05, V-06. 원본 파일 해시/수정 시각 확인은 비식별 시험 자료로 수행한다. 사용자 실제 기록 접근은 범위 검토 후 수행하며 이 문서 작성이 접근 승인을 대신하지 않는다.
