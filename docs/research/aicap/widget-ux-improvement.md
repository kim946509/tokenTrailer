- 요약: `ev_c02f10fa21906cb557c4ebc9362472facf9c2fdbb381ee3aa2912a27a1ff7c93`, `widget-ux-rea-summary.json`에 보존.
- 1개 JS / 51,009 AST 노드 파싱. 나머지 14개 자산은 선택 범위 밖이며 의미 그래프 노드 상한으로 partial이다. 전체 앱 분석 완료나 실행 관찰을 뜻하지 않는다.

## 적용한 UX

- 위젯: 큰 오늘 토큰 카드/반복 설명을 없애고 연결별 작은 한도 행과 막대만 유지. 드래그 헤더와 사용률/시간 전환·새로고침·상세 버튼. 우클릭은 같은 자리의 숫자 전환이며 다시 누르면 복귀. 키보드 버튼/Shift+F10도 제공.
- 작업표시줄: 별도 팝업에 의존하던 우클릭을 네이티브 표시 도우미 안의 상태 전환으로 변경. 왼쪽 클릭은 전체 한도 팝업 유지. 첫 클릭 활성화 처리 및 버튼 누름/뗌 캡처 보강.
- 대시보드: 연결된 AI만 카드/분석 선택지/합계에 포함. 전체·개별 AI 버튼을 그래프 위에 배치. 연결 해제한 기록은 삭제하지 않고 재연결 시 다시 표시.
- 설정: AI별 연결 카드, 접힌 고급 기록 경로, 표시 옵션, 시작 옵션으로 분리. ↑↓ 접근성 이름 유지. 새로고침 문구 통일.

## 검증과 남은 문제

위젯 우클릭 입력, 실행 중 별도 PowerShell 도우미의 실제 HWND에 우클릭 메시지 전달→상태 변경→시간 표시→% 복귀, 설정 저장/순서 변경, 연결 해제 후 카드/필터 숨김 및 기록 유지, 연결 없음 안내를 smoke에서 검증했다.

OS SendInput/mouse_event 자동 주입은 한 차례 시간 전환을 관찰했지만 반복 시험에서 입력 누락이 발생했다. 가려진 창/이동한 포인터는 클릭하지 않도록 검사했다. 이 결과를 실제 마우스 전체 경로 성공으로 기록하지 않는다. 이전 팝업 방식도 메시지 단위 시험만 통과했으므로 사용자가 보고한 실패의 단일 원인을 확정할 수 없다. 현재 변경은 팝업 포커스 경로를 제거하지만 실제 사용자 클릭의 안정성은 후속 확인이 필요하다.

기본 smoke는 실제 helper에 직접 Windows 메시지를 보내는 통합 시험이다. `TT_OS_MOUSE_TEST=1`일 때만 포인터를 옮기는 시험을 수행하며 실패를 숨기지 않는다. 배율/다중 모니터 행렬과 Gemini 실계정 검증은 이번 범위에서 수행하지 않았다.

## 미니멀 위젯·불투명도 추가 분석 (2026-10-20)

사용자 제공 AICap 이미지 2개는 약 233×109 크기의 아이콘/한도/막대/% 또는 남은 시간 행이다. 이 시각적 근거와 위 REA 부모 Evidence를 다시 조회하고 동일 복원 JS를 읽었다. 분석 대상과 해시는 위 기록과 동일하다.

UTF-16 source offsets: `Na` 217743에서 range onChange 임시값 및 onMouseUp 저장. 241936 부근 widgetOpacity 설정은 min:30,max:100 및 value:fe*100, 저장값 fe. 250772 getContainerOpacity는 widgetOpacity 반환. 270030 backgroundColor는 rgba(255,248,239,e.opacity), backdropFilter blur(4px). 창 전체 opacity가 아닌 배경 alpha를 전달하는 정적 코드 근거다. AICap 실제 실행 중 슬라이더 조작을 관찰한 결과는 아니다.

앞선 적용 UX의 헤더/버튼은 이번 사용자 요청으로 제거했다. TokenTrailer는 어두운 기존 테마, 250 DIP 폭, 연결별 기호와 한도 행만 표시한다. 30~100% 배경 불투명도와 기존 즉시 저장을 연결했다. Electron 투명 창에 CSS alpha만 사용하며 blur 효과는 이식하지 않았다. 기호 열로 이동, 본문 더블클릭으로 상세, 우클릭/Shift+F10으로 시간 전환. 상태는 툴팁, 이전 성공값은 기호 아래 점선으로 구분한다.
