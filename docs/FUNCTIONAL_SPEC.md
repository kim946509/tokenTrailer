# TokenTrailer 전체 기능명세

상태: 사용자 검토용 초안(상세 요구사항 연결) · 버전: 0.3 · 작성/수정일: 2026-10-19

### 최신 결정과 상세 요구사항

이 문서의 아래 초기 검토안에서 미정으로 기록된 항목 중 다음은 이후 사용자 답변으로 확정되었다. 충돌하는 초기안보다 이 결정과 [상세 요구사항 검토 목록](../.kiro/specs/README.md)을 우선한다.

- Windows 11, Claude Code·Codex CLI/데스크톱·Gemini CLI를 첫 버전 대상으로 한다. 지원 세부 버전·형식은 검증 후 명시한다.
- F-09 작업표시줄 수치 직접 표시와 F-10 미니 위젯은 필수다. 트레이만으로 대체하지 않는다.
- F-18 계정 요금제의 한도 사용률·초기화 정보는 필수이며 3개 도구 모두 실제 한도 조회가 출시 조건이다. 지원 요금제·로그인 정보 접근 방식은 미정이다.
- 최신 사용자 설명은 금액보다 계정 한도 100% 기준의 사용률을 우선한다. F-19 비용 환산은 첫 버전 필수에서 제외한다.
- 발견한 지원 기록 전체 수집, 원본 삭제 후 앱 이력 유지, 앱 이력 삭제 기능은 승인되었다. 삭제 후 재수입 방지 상세는 검토안이다.
- 2026-10-20 추가 결정: Gemini CLI만 유지하고 Antigravity는 추후 검토. 기존 로그인 읽기·원래 도구의 인증 갱신 방식 승인. 한도 갱신 주기는 AICap처럼 선택 가능하게 한다. 구체 선택지·기본값과 다른 기본 설정은 [설정 검토안](../.kiro/specs/desktop-presence/settings-review.md)을 따른다.

상세 요구사항은 수집·분석·상주 표시·계정 한도의 네 묶음으로 작성했다. 각 문서의 EARS 기준과 결정 목록을 검토한 뒤 design.md, tasks.md로 진행한다. 구현과 실제 동작 검증은 아직 수행하지 않았다.

## 1. 문서의 역할과 결정 상태

이 문서는 TokenTrailer의 전체 기능을 정의하고, 첫 버전에 포함할 기본 기능과 후속 기능을 구분한다. 기술 스택·저장 구조·수집 구현을 결정하는 설계서나 구현 승인을 대신하지 않는다.

| 구분 | 내용 |
|---|---|
| 사용자 방향 | Claude Code·Codex·Gemini CLI 최소 필수, Kimi CLI/Code·Grok Build 추가 지원 목표. 상주 표시·미니 위젯·이해하기 쉬운 그래프로 언제/어떤 작업에 많이 썼는지 확인 |
| 최신 우선순위 | 기본 기능을 먼저 진행하고 PC별 귀속·비율은 보조 기능으로 후속 진행 |
| 이 문서의 제안 | 1차 기능의 세부 범위, 화면 구성, 초기 기본값, 검증 관점 |
| 아직 미정 | 지원 버전·로그 형식, Codex 클라이언트·OS 세부 범위, 작업표시줄 표시 방식, 토큰 합계 정의, 계정 한도 포함 시점 |

2026-10-19 사용자 승인으로 최소 필수 3개 도구와 추가 지원 목표를 반영했다. Grok Bot은 실측 토큰 확보 전까지 보류하며, 웹 채팅·모바일 전체 사용량은 지원 목표에 포함하지 않는다. 나머지 기본값과 기능 상세는 계속 검토용이다.

검토 후 기능별 `.kiro/specs/<기능명>/requirements.md`에 사용자 스토리와 EARS 수용 기준을 작성한다. 그 요구사항을 검토한 뒤 `design.md`, 다시 검토한 뒤 `tasks.md`로 진행한다. 이 문서의 검증 항목은 상세 요구사항을 작성하기 위한 기준이다.

근거 문서:

- [프로젝트 목표](PROJECT_GOALS.md)
- [AICap 분석](research/AICAP_ANALYSIS.md)
- [CodeBurn 분석](research/CODEBURN_ANALYSIS.md)

프로젝트 목표의 선행 조사 표는 조사 전 시점의 기록이다. 현재 조사 수준은 위 두 분석 보고서를 따른다. 지원 우선순위는 프로젝트 목표와 이 문서에 동일하게 반영한다.

## 2. 제품 목적과 첫 버전의 범위

사용자는 다음 세 질문에 답할 수 있어야 한다.

1. **얼마나 사용했는가:** 선택한 기간의 Claude Code·Codex·Gemini CLI 토큰 사용량.
2. **언제 많이 사용했는가:** 시간·일별 사용량이 집중된 구간.
3. **어떤 작업에서 사용했는가:** 해당 구간에 사용한 프로젝트와 세션.

다른 작업 중에는 상주 표시와 미니 위젯으로 요약을 확인하고, 상세 화면에서 같은 수치의 근거를 추적한다.

1차에서는 '작업'을 확인 가능한 **프로젝트·세션**으로 표현한다. '버그 수정', '문서 작성' 등의 자동 분류와 PC별 귀속·동기화는 후속 기능이다. 자동 분류가 없어도 시간 구간에서 관련 프로젝트·세션으로 내려갈 수 있어야 한다.

### 범위 등급

| 등급 | 의미 |
|---|---|
| 1차 | 첫 버전 기본 기능으로 제안. 사용자 검토 후 세부 요구사항 확정 |
| 후속 | 전체 제품 범위에 포함하되 1차 완료 조건에서 제외 |
| 범위 결정 필요 | 필요성 또는 포함 시점을 아직 정하지 않음. 기본 포함으로 간주하지 않음 |
| 제외 | 비교 제품에 있더라도 현재 목표에 포함하지 않음 |

## 4. 공통 용어와 지표 계약

| 용어 | 이 문서에서의 의미 |
|---|---|
| 도구 | Claude Code·Codex·Gemini CLI 등 수집 대상. CLI·데스크톱·웹 지원은 각각 구분 |
| 데이터 출처 | 지원 클라이언트가 남긴 특정 형식의 기록 또는 별도 승인된 조회 경로 |
| 프로젝트 | 기록에서 확인한 작업 공간. 이름이 같아도 경로/식별자가 다르면 별개로 구분 가능해야 함 |
| 세션 | 한 도구의 대화·실행 기록 묶음. 도구가 다른 동일 ID를 같은 세션으로 합치지 않음 |
| 선택 사용량 | 현재 기간·도구·프로젝트 등의 필터에 해당하는 사용량 |
| 세션 전체 사용량 | 확보된 해당 세션 기록 전체의 사용량. 선택 사용량과 별도 표시 |
| 수집된 사용량 | 앱이 확보한 출처의 사용량. 계정 전체 또는 실제 이 PC 발생량을 자동으로 뜻하지 않음 |
| 계정 한도 사용률 | 제공자가 보고하는 한도 기준 비율. 소비 토큰의 분모로 대체하지 않음 |

### 공통 동작 원칙

- **지표 일치:** 같은 기간·필터·지표·갱신 기준이면 요약·그래프·목록·위젯의 합계가 같아야 한다. 범위가 다르면 각 화면에 그 차이를 표시한다.
- **중복 없는 토큰 정의:** 입력·출력·캐시 읽기/쓰기·추론의 포함 관계를 도구별로 정의한다. 이미 입력/출력에 포함된 항목을 다시 더하지 않는다. 최종 합계 산식은 D-04에서 결정한다.
- **부분합 표시:** 지원하지 않는 토큰 종류가 있으면 완전한 전체 합계로 표현하지 않는다. 추정치·부분 기록을 실측 전체처럼 보이게 하지 않는다.
- **상태 구분:** 성공적으로 읽은 0, 기록 없음, 수집 실패, 지원하지 않는 형식, 일부 누락을 구분한다.
- **시간 기준:** 조회 시간대와 기간 경계를 표시한다. 선택 기간의 끝을 배타적으로 처리하는 등 경계 규칙을 상세 요구사항에서 고정한다. 자정을 넘는 세션은 각 사용 기록의 시각 기준으로 나눈다.
- **귀속 보존:** 시각/프로젝트/세션을 모르는 기록을 임의로 끼워 넣거나 조용히 버리지 않는다. 해당 분석에서 제외된 수량 또는 미귀속 상태를 알려준다.
- **관측 범위:** 데이터가 이 PC에 있다는 이유로 이 PC에서 발생한 사용량이라고 단정하지 않는다. 1차에서는 '수집된 기록 기준'으로 설명한다.

## 5. 1차 기능 상세

### F-01. 최초 설정·데이터 출처 확인

**목적:** 사용자가 연결 가능한 Claude Code·Codex·Gemini CLI 출처와 수집 범위를 확인한다.

- 지원 대상과 발견 여부, 읽을 기록의 종류를 보여준다. 자동 탐색 범위 및 수동 경로 지정 지원은 D-02에서 확정한다.
- 한 도구의 기록이 없어도 나머지 도구의 설정과 조회를 진행할 수 있다.
- 최초 수집 진행·완료·실패를 구분하며, 실패 시 확인 가능한 이유와 재시도 진입점을 제공한다.
- 데이터 숫자 외 제목·경로·도구 기록·대화 내용의 접근이 필요한지는 별도로 설명한다. 토큰 분석을 이유로 계정 인증정보 접근을 자동 포함하지 않는다.

**검증 관점:** 필수 3개 도구 모두 존재/일부만 존재/출처 없음/접근 불가에서 각각 올바른 상태를 표시하고 앱이 사용 가능하다.

### F-02·F-03·F-20. Claude Code·Codex·Gemini CLI 수집

**목적:** 승인된 클라이언트 범위의 사용량을 분석 가능한 형태로 확보한다.

Gemini CLI는 F-20으로 추가하여 기존 기능 ID를 유지한다. Gemini 웹·모바일 또는 Antigravity 사용량까지 지원한다고 해석하지 않는다. Gemini 기록의 입력·캐시·출력·추론 토큰 포함 관계도 공통 정규화 검증 대상이다.

- 사용 시각, 토큰 종류별 값, 도구, 가능한 모델·프로젝트·세션 식별 정보를 읽는다.
- 발견한 모든 로그 형식을 지원한다고 가정하지 않는다. 지원하지 않는 버전·형식은 사용자에게 구분해 표시한다.
- 필수 필드가 없는 기록은 0으로 채우지 않고 불완전 상태로 처리한다. 문자 수로 토큰을 추정하는 기능은 1차 기본값으로 포함하지 않는 안을 제안한다.
- 기록을 읽는 중 추가되는 데이터와 손상된 일부 기록 때문에 정상 기록까지 전부 사용할 수 없게 되지 않아야 한다.
- 원본 로그·클라이언트 설정·인증 파일을 변경하지 않는다. 계정 전환이나 자동 모델 요청을 수행하지 않는다.

**검증 관점:** 정상/빈/일부 손상/기록 증가/지원하지 않는 형식의 합성 데이터로 기대한 합계와 상태를 확인한다. 지원 클라이언트와 버전별 검증 자료는 requirements에서 지정한다.

### F-04. 정규화·중복 처리

**목적:** 여러 원시 형식을 같은 지표로 비교하고 재수집으로 인한 과대 집계를 방지한다.

- 동일 기록을 반복 읽어도 사용량이 증가하지 않는다. 재시작 후에도 같은 기준을 유지한다.
- 누적 수치와 개별 사용 수치를 구분한다. streaming 갱신·archive·fork 등은 지원 형식의 계약에 따라 처리한다.
- 계정/도구/프로젝트가 다를 수 있는 같은 ID를 임의로 합치지 않는다. 식별 불가 상태를 보존한다.
- 원본 기록이 삭제·회전되었을 때 확보한 이력을 유지할지와 보존 기간은 D-06에서 정한다. 재수집이 기존 기록을 조용히 중복 또는 삭제하지 않도록 한다.

**검증 관점:** 동일 파일 재수집·동일 이벤트 복사·누적값 재전송·분기 세션 등의 지원 사례에서 기대 결과를 확인한다. 식별 근거가 없는 경우 완전한 중복 제거를 보장한다고 표시하지 않는다.

### F-05. 요약·기간/도구 필터

**목적:** 선택 범위의 사용량을 빠르게 이해한다.

- 첫 화면에 토큰 요약, Claude Code/Codex/Gemini CLI별 수치, 선택 기간, 마지막 갱신·부분 실패 상태를 표시한다.
- 기본 조회는 오늘, 기간 선택은 오늘/이번 주/이번 달을 제안한다. 주 시작일·시간대는 D-05에서 정한다.
- 도구 선택은 전체/Claude Code/Codex/Gemini CLI를 제공한다. 전체는 확보된 지원 도구 기록의 합계이며 계정 전체 사용량이 아니다.
- 토큰 구성의 설명과 세부 값을 확인할 수 있게 한다. 비용·한도 %가 토큰 수를 대체하지 않는다.
- 필터 변경 시 요약·그래프·프로젝트·세션 목록이 동일한 조건을 사용한다.

**검증 관점:** 같은 필터의 합계가 상세 목록과 일치하고, 한 도구 수집 실패가 전체를 정상 0으로 바꾸지 않는다.

### F-06. 시간·일별 그래프

**목적:** 토큰 소비가 집중된 구간을 찾는다.

- 오늘은 시간별, 주간·월간은 일별 막대그래프를 초기안으로 제안한다. 임의의 세부 시간 선택은 후속 검토하며 1차 필수로 늘리지 않는다.
- 축의 지표·단위·기간·시간대를 표시하고 구간별 정확한 수치를 확인할 수 있게 한다.
- 구간을 선택하면 같은 화면의 프로젝트·세션 분석 범위를 해당 구간으로 좁힌다. 선택 해제로 기존 기간에 돌아간다.
- 데이터가 비어 있는 구간과 수집 실패 때문에 알 수 없는 구간을 구별한다. 색상만으로 상태를 전달하지 않는다.
- 그래프에서 토큰 정의를 바꾸지 않는다. 누락·미귀속 때문에 요약과 차이가 있으면 이유를 표시한다.

**검증 관점:** 자정·기간 경계와 빈 구간에서 합계가 유지되고, 선택한 막대의 수치가 하위 목록의 기여량과 일치한다.

### F-07. 프로젝트별 사용량

**목적:** 선택한 기간에 어떤 프로젝트가 사용량을 차지했는지 확인한다.

- 프로젝트명, 구분 가능한 작업 공간 정보, 도구별/합계 사용량을 제공한다. 초기 정렬은 사용량 내림차순을 제안한다.
- 프로젝트를 선택하면 현재 기간·도구 조건을 유지하며 세션 목록으로 이동한다.
- 같은 이름의 다른 작업 공간을 구별하고, 귀속 정보가 없는 기록은 '프로젝트 미확인'으로 구분한다.
- 상위 일부만 표시하면 나머지 항목이 존재함을 알려주고 전체 목록으로 접근할 수 있게 한다.

**검증 관점:** 이름이 같은 다른 경로와 미귀속 기록이 사라지거나 잘못 합쳐지지 않으며, 전체 목록의 합계가 선택 범위와 일치한다.

### F-08. 세션 목록·상세

**목적:** 프로젝트에서 어떤 실행·대화 세션이 토큰을 소비했는지 확인한다.

- 확인 가능한 세션명 또는 식별자, 도구, 시각, 모델, 선택 범위의 토큰 사용량을 보여준다. 대화 원문 기반 자동 제목 생성은 기본 기능으로 포함하지 않는다.
- 상세에는 토큰 구성, 확보된 시간 분포, 관련 프로젝트와 데이터 상태를 제공한다.
- 선택 기간의 기여량과 확보된 세션 전체 사용량을 구분한다. 기간 밖 수치를 선택 합계에 섞지 않는다.
- 뒤로 이동할 때 기간·도구·프로젝트 선택을 유지한다.
- 요청별 상세 시각이 없으면 더 정밀한 분포를 만들어 내지 않고 가능한 수준만 표시한다.

**검증 관점:** 여러 날짜에 걸친 세션, 제목 없는 세션, 도구별 동일 ID, 일부 기록만 남은 세션을 올바르게 구별한다.

### F-09. 작업표시줄·트레이 상주 표시

**목적:** 다른 작업 중에 사용량을 확인하고 상세 화면에 진입한다.

표시 형태는 다음을 구분하여 D-03에서 선택한다.

| 형태 | 사용자에게 보이는 결과 | 결정할 내용 |
|---|---|---|
| 시스템 트레이 | 알림 영역의 아이콘과 요약 팝업 | 클릭해야 수치가 보여도 충분한지 |
| 트레이 숫자 표시 | 작은 아이콘 영역에 요약 수치 표시 | 가독성과 표시 가능한 글자 수가 목표에 맞는지 |
| 작업표시줄 직접 표시 | 작업표시줄 영역에서 수치가 계속 보임 | 직접 표시가 필수인지, 지원 OS/환경과 복구 기준 |

- 선택한 상주 표면에서 표시 지표·기간·도구 범위를 확인할 수 있고, 클릭으로 상세 화면을 연다.
- 상세 열기, 수동 갱신, 위젯 표시/숨김, 설정, 앱 종료에 접근할 수 있게 한다. 정확한 메뉴 위치는 설계 단계에서 정한다.
- 표시 실패와 수집 실패를 구분한다. 표면 재생성 시 같은 표시가 중복으로 남지 않는다.
- 작업표시줄 직접 표시가 필수로 확정되면 트레이만 구현한 상태로 완료 처리하지 않는다.

**검증 관점:** 앱 시작, 상세 창 닫기, OS 셸 재시작, 배율·모니터 변화에서 접근성과 표시 상태를 확인한다. 실행 프로세스 존재만으로 표시 성공을 판정하지 않는다.

### F-10. 미니 위젯

**목적:** 작은 독립 창에서 요약을 지속적으로 확인한다.

- 표시/숨김, 이동, 마지막 유효 위치 복원, 상세 화면 열기를 지원한다. 항상 위 표시 설정을 초기안에 포함한다.
- 초기 지표는 오늘의 토큰과 Claude Code/Codex/Gemini CLI 구분을 제안한다. 별도의 위젯 전용 집계 산식을 만들지 않는다.
- 기간·대상 도구·마지막 성공 갱신 시각과 오래된 데이터/실패 상태를 식별할 수 있게 한다.
- 모니터 연결 해제나 배율 변화로 저장 위치가 화면 밖이 되면 접근 가능한 위치로 돌아온다.
- 일시적인 수집 실패만으로 사용자의 위젯 표시 설정을 꺼진 값으로 저장하지 않는다.

**검증 관점:** 같은 범위의 상세 수치와 일치하고, 모니터 변화·앱 재시작·수집 실패 후에도 숨김 설정과 오류 상태를 혼동하지 않는다.

### F-11. 자동 시작·창 표시·종료

**목적:** 사용자가 지정한 방식으로 앱을 시작하고 종료한다.

- '로그인 시 자동 시작'과 '시작 시 상세 창 숨김'은 독립 설정이다.
- '상세 창 닫기'와 '앱 종료'를 구분한다. 창 닫기 시 상주 유지 여부와 초기 기본값은 D-07에서 확정한다.
- 명시적 종료는 백그라운드 갱신과 상주 창을 종료한다. 수동 실행으로 동일 인스턴스가 중복되지 않게 한다.
- 자동 시작 등록 상태, 프로세스 실행, 상주 표면 표시, 데이터 갱신 상태를 별도 검증한다.
- 로그인 직후 표시 환경이 아직 준비되지 않은 경우의 복구 기준을 상세 요구사항에 포함한다.

**검증 관점:** 자동 시작/창 숨김의 조합, 실제 로그인, 수동 재실행, 명시적 종료 후의 프로세스·창 상태를 확인한다.

### F-12. 갱신·오류·데이터 상태

**목적:** 수치가 최신인지와 실패 원인을 사용자가 알 수 있게 한다.

- 자동 갱신과 수동 갱신을 제공한다. 간격·동시 요청·재시도 제한은 D-08에서 정한다.
- 도구별 마지막 성공 시각과 현재 갱신 상태를 표시한다. 갱신 실패 시 이전 성공값을 보존하되 현재 정상값처럼 표현하지 않는다.
- 한 도구의 오류가 다른 도구의 정상 데이터를 숨기지 않는다. 전체 합계가 부분 데이터라면 표시한다.
- 자동 갱신 실패마다 반복 팝업을 띄우지 않고 지속 상태와 재시도 경로로 알린다.
- 초기 수집 중, 사용 기록 없음, 접근 거부, 지원하지 않는 형식, 일부 누락, 갱신 실패를 구분한다.

**검증 관점:** 성공 후 실패, 일부 도구 실패, 실패 후 복구에서 값·시각·상태가 일관되며 실패를 0으로 표시하지 않는다.

### F-13. 기본 설정·설정 저장

**목적:** 사용자가 수집·표시·시작 동작을 조절한다.

- 지원 출처, 갱신 주기, 자동 시작, 시작 시 창 표시, 상주 표면, 위젯 표시·위치·항상 위를 설정한다. 승인되지 않은 옵션은 임의로 늘리지 않는다.
- 설정 저장 실패를 사용자에게 알리고 실제 적용 상태와 화면 선택이 다르면 구분한다. 저장에 실패한 값을 완료된 것처럼 표시하지 않는다.
- 재시작 후 설정을 복원하며 손상된 설정을 정상 빈 설정과 구분한다. 자동 초기화로 기존 선택을 조용히 덮어쓰지 않는다.
- 한국어 UI를 초기안으로 제안한다. 추가 언어, 테마·투명도 등 장식 옵션은 1차 필수 범위로 두지 않는다.

**검증 관점:** 저장 성공/권한 오류/손상/재시작에서 저장 결과와 실제 동작이 일치한다. 마우스뿐 아니라 키보드 변경도 저장된다.

## 6. 후속·범위 결정 기능

| ID | 범위 | 선행 조건과 완료 판단 관점 |
|---|---|---|
| F-14 | Kimi CLI/Code·Grok Build 수집 | 추가 지원 목표. Kimi의 usage 기록과 Grok Build의 실측 기록이 있는 형식부터 실제 Windows 자료로 검증. 구형 추정 전용 기록은 실측으로 합산하지 않음. 같은 지표 계약과 검증 자료를 통과해야 함 |
| F-15 | 작업 종류 분류 | 프로젝트·세션 분석 위에 추가. 분류는 추정임을 표시하고 한국어 품질·정정 방법·미분류 처리 검토 |
| F-16 | 실제 PC별 귀속 | 파일 발견 기기와 실행 기기 구분. 복사 로그·원격 미러·WSL·공유 PC를 검토하고 알 수 없는 귀속을 유지 |
| F-17 | 여러 PC 집계·비율 | 수집 범위·계정·기간·지표·기기간 중복 계약을 확보. 미접속 기기와 부분 분모를 표시. 전체 미확보/분모 0이면 유효한 비율을 만들지 않음 |
| F-18 | 계정 한도·초기화 | 1차 필수 승인. 필수 3개 도구 실제 조회가 출시 조건. 지원 요금제·인증 접근 방식은 상세 요구사항에서 검토 |
| F-19 | 비용 추정 | 최신 사용자 설명에 따라 첫 버전 필수 제외. 추후 요청 시 참고 비용과 실제 청구액을 분리하여 검토 |

후속 기능은 현재의 1차 완료를 막지 않는다. 다만 1차에서 수집된 값의 출처와 기간을 잃지 않아야 하며, 이 원칙이 동기화 서버나 복잡한 확장 구조를 미리 구현하라는 뜻은 아니다.

Grok Bot은 F-14의 Grok Build와 별개다. 조사한 로컬 미러에는 실측 토큰이 없어 보류한다. 추가 도구의 목표 확정은 지원 완료 선언이 아니며, 실측 자료 검증 결과에 따라 지원 버전·형식을 명시한다.

## 7. 화면 목록과 주요 흐름

| 화면 | 주요 내용 | 연결 기능 |
|---|---|---|
| 최초 설정 | 지원 출처·발견 상태·수집 범위·초기 수집 결과 | F-01~F-03, F-20 |
| 대시보드 | 기간/도구 필터 → 토큰 요약 → 시간 그래프 → 프로젝트/세션 | F-05~F-08, F-12 |
| 세션 상세 | 선택 기여량·전체 확보량·토큰 구성·시각·모델·출처 상태 | F-08 |
| 상주 표면 | 짧은 요약·상태·상세/위젯/설정/종료 진입 | F-09, F-11, F-12 |
| 미니 위젯 | 요약·상태·위치 이동·상세 진입 | F-10, F-12 |
| 설정 | 출처·갱신·자동 시작·창 표시·상주 표면·위젯 | F-13 |

```text
처음 사용: 출처 확인 → 초기 수집 → 데이터/오류 상태 확인 → 대시보드

소비 탐색: 기간·도구 선택 → 시간 구간 선택 → 프로젝트 선택 → 세션 상세
            ← 선택 해제 또는 뒤로 이동 시 기존 필터 유지 ←

작업 중 확인: 상주 표시 또는 위젯 → 같은 범위의 상세 화면

오류 확인: 오래된 값/부분 실패 표시 → 도구별 원인 확인 → 재시도 → 상태 복구
```

화면 전환 방식과 배치는 설계에서 구체화하되, 사용자가 선택한 범위가 이동 중 조용히 바뀌지 않아야 한다.

## 8. 품질·데이터 처리 조건

| 관점 | 전체 기능에 적용할 조건 |
|---|---|
| 정확성 | 같은 범위의 화면 간 합계 일치, 캐시/추론 이중 합산 방지, 중복·부분 기록 검증 |
| 안정성 | 수집 실패와 표시 실패 분리, 재시작·셸 재시작·절전 복귀·모니터 변경 검증 |
| 성능 | 대규모 기록 수집 중에도 UI 사용 가능. 초기 수집/증분 갱신/화면 응답·CPU·메모리 목표는 D-08에서 데이터 규모와 함께 결정 |
| 접근성 | 키보드로 필터·그래프 구간의 동등한 목록·설정·종료에 접근. 색상·hover만으로 필수 정보를 전달하지 않음 |
| 개인정보 | 접근할 메타데이터/내용 범위를 정의하고 필요한 최소 정보만 보유. 계정 비밀정보와 대화 원문을 진단 로그에 기록하지 않음 |
| 외부 전송 | 1차 기본안은 로컬 분석. 원격 로그 전송·조직 sync·기기 공유를 기본 포함하지 않음. 별도 검토 없이 추가하지 않음 |
| 변경 경계 | 원본 도구의 설정·인증 파일·대화 기록을 수정하거나 자동 요청을 보내지 않음 |
| 검증 자료 | 초기 자동 검증은 합성 또는 비식별 자료 사용. 실제 사용자 로그 검증이 필요하면 접근 범위를 별도 검토 |

## 9. 현재 제외 범위

비교 앱의 모든 기능을 재현하는 것이 목표가 아니다. 현재 범위에는 다음을 포함하지 않는다.

- 계정 전환, 인증정보 원문 보기/복사/내보내기, 다른 도구의 인증 파일 수정.
- 사용 창 시작용 자동 채팅, 한도 초기화 크레딧 사용, 자동 모델 선택·설정 변경.
- 예산 초과 시 도구 실행 차단, hook 설치, MCP 서버 제공, 조직 관제.
- PR·코드 생존율·생산성 점수·절감 최적화 분석.
- 클라우드 백업·복원·로그 외부 전송·자동 업데이트·보고서 내보내기.

마지막 항목들은 현재 요청으로 필수성이 정해지지 않은 부가 기능이며, 이후 별도 요청 시 범위를 다시 검토할 수 있다.

## 11. 1차 완료 판단과 다음 문서

기능명세 검토 후 상세 요구사항에서 다음을 시험 가능한 조건으로 고정한다.

1. 승인된 Claude Code·Codex·Gemini CLI 클라이언트 범위의 기준 데이터에서 기대 토큰 값과 중복 처리 결과가 일치한다.
2. 요약 → 시간 구간 → 프로젝트 → 세션으로 범위를 좁힐 때 합계·선택 기여량을 추적할 수 있다.
3. 승인된 작업표시줄/트레이 방식과 미니 위젯에서 요약·오류·마지막 갱신을 확인할 수 있다.
4. 로그인·재시작·셸 재시작·절전 복귀·모니터 변화에서 표시와 접근성이 요구된 수준으로 복구된다.
5. 수집·설정 저장 실패가 정상 0 또는 저장 성공으로 표시되지 않는다.
6. 데이터 접근·보존 범위가 문서와 일치하며 사용자 도구의 파일을 수정하지 않는다.
7. D-01~D-09 중 1차에 영향을 주는 결정과 성능·복구 기준을 확정하고 그 기준으로 검증한다.

Kimi CLI/Code·Grok Build 추가 지원과 PC별 귀속·여러 기기 합계·자동 작업 분류는 위 최소 1차 완료 조건에 포함하지 않는다.

요구사항 문서는 다음 세 묶음으로 나누는 안을 제안한다. 공통 기능 ID를 유지하여 문서 간 중복 정의를 피한다.

| 예정 경로 | 포함 기능 |
|---|---|
| `.kiro/specs/usage-collection/requirements.md` | F-01~F-04, F-20, F-12의 수집 상태·갱신, 데이터 계약 |
| `.kiro/specs/usage-analysis/requirements.md` | F-05~F-08, 공통 조회·지표·탐색 흐름 |
| `.kiro/specs/desktop-presence/requirements.md` | F-09~F-11, F-13, 상주 상태 표시·설정 |

상세 요구사항 초안은 문서 상단의 검토 목록에 연결했다. 아래 세 묶음에 account-quota/requirements.md(F-18)를 추가한 네 묶음이다. 설계·작업 계획은 요구사항 검토 후 진행한다.
