# TokenTrailer 프로젝트 목표

2026-10-20 현재 상태: 이 문서 아래는 초기 목표 기준이다. 이후 조사·요구사항·구현 진척은 [MVP 설계](MVP_DESIGN.md)와 [MVP 검증 결과](research/validation/2026-10-20-mvp.md)를 따른다. 로컬 MVP를 구현했으며 Gemini 실계정과 Windows 복구 행렬은 출시 미검증 상태다.

상태: 검토용 초안 · 작성일: 2026-10-19

## 목적

TokenTrailer는 사용자가 AI 토큰을 얼마나 사용했는지, 언제 많이 사용했는지, 어떤 작업에서 많이 사용했는지 쉽게 파악하도록 돕는 개인용 도구다.

작업 중에는 작업표시줄이나 미니 위젯에서 사용량을 확인하고, 상세 화면에서는 시간과 작업에 따른 사용 패턴을 그래프로 살펴볼 수 있도록 한다.

## 배경

사용자는 AICap의 작업표시줄 표시와 미니 위젯에서 오류를 경험했으며, 사용량 시각화 기능도 부족하다고 느꼈다. CodeBurn은 사용량 분석을 제공하지만 정보를 이해하기 어렵다고 느꼈다. 이는 사용자의 경험 보고이며, 구체적인 오류와 원인은 아직 검증하지 않았다.

공유 계정을 사용하거나 회사·집 등 여러 PC를 오가는 상황에서는 계정 전체 사용량만으로 현재 PC에서 얼마나 사용했는지 알기 어렵다. 현재 PC의 사용량을 별도로 확인하고, 비교 가능한 전체 데이터가 확보되면 그 비율도 확인하고자 한다.

## 지원 우선순위

| 우선순위 | AI 도구 | 범위 |
| --- | --- | --- |
| 1순위·최소 필수 | Claude Code, Codex, Gemini CLI | 사용자 승인한 첫 버전 최소 지원 목표. 지원 버전·로그 형식과 Codex 클라이언트 세부 범위는 요구사항에서 확정 |
| 2순위·추가 지원 목표 | Kimi CLI / Kimi Code, Grok Build | 실측 토큰 기록을 확보할 수 있는 형식부터 지원. 실제 Windows 기록 검증 후 지원 범위 확정 |
| 보류 | Grok Bot | 조사한 로컬 미러에서는 실측 토큰 없이 문자 수로 추정하므로 정확한 토큰 집계 목표에서 보류 |

2026-10-19 사용자 승인으로 Gemini CLI를 최소 필수에 포함하고 Kimi·Grok Build를 추가 지원 목표로 정했다. 각 서비스의 웹 채팅·모바일 전체 사용량은 이 지원 목표에 포함하지 않는다. 이는 지원 목표의 확정이며 구현·검증 완료를 뜻하지 않는다.

필수 도구에서 요구하는 데이터를 확보할 수 없다면 제약과 대안을 보고하고 요구사항 검토를 받는다. 지원 가능 여부를 확인하기 전에 지원 완료를 약속하지 않는다.

## 주요 기능 목표

### 작업표시줄 표시

사용자가 다른 작업을 하면서도 AI 사용량을 확인할 수 있어야 한다. 표시 위치, 지표와 상세 화면 진입 방식은 요구사항 단계에서 정한다. 작업표시줄 내 직접 표시와 시스템 트레이 표시는 구분해서 검토한다.

### 미니 위젯

작은 창에서 사용량을 확인할 수 있어야 한다. 작업표시줄·위젯·상세 화면은 같은 범위의 데이터를 볼 때 일관된 수치를 보여줘야 하며, 갱신 실패나 오래된 데이터 상태를 사용자가 알 수 있어야 한다.

### 시간별 사용량 시각화

사용자가 그래프를 통해 사용량이 집중된 시점을 쉽게 찾을 수 있어야 한다. 시간·일별 등 집계 간격, 조회 기간과 시간대 기준은 요구사항 단계에서 정한다.

### 작업별 사용량 파악

사용자가 사용량이 많은 시점과 관련된 작업을 확인할 수 있어야 한다. 프로젝트·세션 등 실제 기록에서 확인 가능한 연결을 먼저 조사한다. ‘버그 수정’, ‘문서 작성’ 같은 작업 유형 분류는 별도 검증이 필요한 후보이며 확정 기능이 아니다.

## 보조 기능 목표: 현재 PC 사용량과 비율

현재 PC에서 발생한 사용량을 계정 전체 사용량과 구분해서 확인할 수 있도록 한다.

비율의 검토 기준은 다음과 같다.

```text
현재 PC 사용 비율(%) = 현재 PC 사용량 / 같은 계정·기간·집계 기준의 전체 사용량 × 100
```

전체 데이터가 없거나 집계 기준이 다르면 이 비율을 계산하지 않는다. 분모가 0이거나 데이터가 불완전한 경우의 표시는 요구사항에서 정한다. 요금제 사용률을 토큰 수의 분모로 사용할 수 있다고 가정하지 않는다.

PC별 구분은 사용자별 구분과 다르다. 한 PC를 여러 사람이 사용하거나 기록을 다른 PC로 복사한 경우에도 개인별 사용량을 정확히 식별할 수 있는지는 미정이다. 여러 PC 데이터의 수집·동기화와 중복 제거 방식 역시 조사 후 결정한다.

## 선행 조사

| 대상 | 확인할 내용 | 현재 확인 수준 |
| --- | --- | --- |
| AICap | 사용량 데이터 출처, 갱신 방식, 작업표시줄·위젯 구현과 보고된 오류 원인 | 로컬 설치 실행 파일을 REA로 식별함. 기능 내부와 오류 원인은 미분석 |
| CodeBurn | 사용량 수집·집계, 프로젝트·세션 연결, 그래프와 화면 구성 | 공식 사이트 안내 확인. 소스·배포물·실행 동작은 미분석 |
| 지원 AI 도구 | 토큰 수·요금제 사용률·계정·시각·작업·PC 귀속 정보의 확보 가능성 | 미검증 |

AICap의 배포물 분석에는 REA를 사용한다. CodeBurn은 공개 소스로 확인 가능한 내용은 소스 분석을 우선하고, 배포물이나 런타임 확인이 필요한 부분에 REA를 사용한다.

조사는 기능을 이해하고 설계 근거를 확보하기 위한 것이다. 비교 앱의 오류 수정은 현재 작업 범위에 포함하지 않는다.

## 개발 순서와 산출물

목표 검토 → 선행 조사 → 요구사항 검토 → 설계 검토 → 작업 계획 검토 → 요청된 작업 구현 순서로 진행한다.

| 문서 | 역할 |
| --- | --- |
| `AGENTS.md` | 작업 범위, 검토 절차와 근거 처리 원칙 |
| `docs/PROJECT_GOALS.md` | 프로젝트 목적, 기능 목표와 미정 사항 |
| `.kiro/specs/<기능명>/requirements.md` | 사용자 스토리와 검증 가능한 수용 기준 |
| `.kiro/specs/<기능명>/design.md` | 수집·저장·집계·표시 구조 및 기술 선택 |
| `.kiro/specs/<기능명>/tasks.md` | 요구사항에 연결된 구현 작업과 검증 방법 |

각 단계의 검토를 마친 뒤 다음 단계로 진행한다. 이 문서는 세부 스펙이나 구현 승인을 대신하지 않는다.

## 성공 판단 기준

- 사용자가 사용량이 집중된 시점과 관련 작업을 쉽게 찾을 수 있다.
- 작업표시줄과 위젯에서 일관된 사용량 및 갱신 상태를 확인할 수 있다.
- 현재 PC의 사용량과 계정 전체 사용량을 혼동하지 않는다.
- 데이터가 없거나 불완전한 경우 그 한계를 확인할 수 있다.
- 수용 기준과 시험 시나리오를 통해 필수 지원 도구의 동작을 검증할 수 있다.

응답 속도, 갱신 주기, 자원 사용량, 수치 정확도 등 정량 기준은 조사 후 요구사항 검토에서 정한다.

## 미정 사항과 현재 제외 범위

- 필수 도구의 지원 버전·로그 형식과 Codex 클라이언트 세부 범위, Kimi·Grok Build의 실제 Windows 기록 지원 범위
- 작업표시줄 내 직접 표시 여부와 표시할 지표
- 계정 식별, 전체 사용량 확보와 여러 PC 데이터 결합 방식
- 토큰 종류별 집계, 누적 기록의 중복 제거와 계정 전환 처리
- 작업의 정의와 자동 분류 여부
- 지원 운영체제, 기술 스택, 저장 위치와 보존 기간
- 대화 원문 접근 필요성 및 외부 전송·동기화 여부

현재 문서 작성에는 앱 구현, 패키지 설치, 계정·환경 설정 변경, 비교 앱 수정, 커밋·푸시·배포를 포함하지 않는다.
