# TokenTrailer

**AI 코딩 도구의 로컬 토큰 사용량과 계정 한도를 한곳에서 확인하는 Windows 데스크톱 앱입니다.**

Claude Code, Codex CLI·데스크톱, Gemini CLI의 로컬 기록을 모아 언제, 어떤 프로젝트와 세션에서 토큰을 많이 사용했는지 보여줍니다. 작업 중에는 미니 위젯과 Windows 작업표시줄에서 계정 한도 사용률과 초기화까지 남은 시간을 확인할 수 있습니다.

현재 버전은 **0.1.0 로컬 MVP**입니다. Gemini 실계정 검증과 Windows 환경별 복구 검증이 남아 있으며, 정식 출시 검증을 마친 제품은 아닙니다.

## 주요 기능

- **사용량 대시보드**: 오늘·이번 주·이번 달의 토큰 합계, 시간별·일별 그래프, AI별 사용량과 구성 비율을 확인합니다.
- **프로젝트·세션 탐색**: 그래프 구간과 프로젝트를 선택해 관련 세션과 토큰 구성으로 좁혀 봅니다. 토큰 수는 축약 표시하고 마우스를 올리면 정확한 값을 보여줍니다.
- **계정 한도 조회**: 원래 도구의 기존 로그인 정보를 읽어 제공자 API에서 한도 사용률과 초기화 정보를 조회합니다. 로컬 기록 수집과 별도로 연결할 수 있습니다.
- **작업표시줄 직접 표시**: 연결 순서 상위 2개 AI의 주요 한도를 표시합니다. 더블클릭하면 메인 창을 열거나 복원하고, 우클릭하면 전체 연결의 한도별 남은 시간 정보창을 엽니다. 단일 왼쪽 클릭은 동작하지 않습니다.
- **미니 위젯**: 연결된 AI의 한도를 250px 폭의 작은 창에 표시합니다. 우클릭 또는 Shift+F10으로 사용률과 남은 시간을 전환하며, 기호를 끌어 이동하고 본문을 더블클릭해 상세 창을 엽니다. 항상 위·위치·배경 불투명도를 설정합니다.
- **트레이 상주와 이력 관리**: 창을 닫아도 상주합니다. 자동 시작과 시작 시 상세 창 숨김을 각각 설정하고, 수집 이력 삭제와 과거 기록 재수입을 관리합니다.

## 지원 범위

| 도구 | 로컬 기록 수집 | 계정 한도 | 검증 상태 |
| --- | --- | --- | --- |
| Claude Code | `projects` 아래 JSONL | 기존 로그인 기반 조회 | 기존 검증 기록에서 실제 로컬 수집·한도 응답 확인 |
| Codex CLI·데스크톱 | `sessions`, `archived_sessions` 아래 JSONL | 기존 로그인 기반 조회 | 기존 검증 기록에서 두 클라이언트 기록·한도 응답 확인 |
| Gemini CLI | `tmp` 아래 `chats`의 JSON·JSONL | 기존 로그인 기반 조회 | 구현·합성 테스트 완료, 실계정 검증 필요 |

도구 버전·로그 형식·계정 유형에 따라 지원 여부가 달라질 수 있습니다. 위 표의 실제 조회는 기존 검증 보고서의 결과이며, 모든 요금제와 최신 버전을 보장하지 않습니다.

로컬 토큰 수와 요금제 한도 사용률은 별도 지표입니다. AI별 토큰 비율은 선택한 로컬 기록 합계 기준이며, 계정 전체 사용량이나 요금제 사용률을 뜻하지 않습니다. 현재 PC에서 발견한 기록을 특정 개인이나 현재 로그인 계정의 사용량으로 단정하지 않습니다.

## 소스에서 실행

Windows 11, Node.js 22.12 이상, npm, Windows PowerShell이 필요합니다. UI는 Electron, 작업표시줄 표시는 PowerShell과 C#/Win32 보조 프로세스로 구현되어 있습니다.

```powershell
git clone https://github.com/kim946509/tokenTrailer.git
cd tokenTrailer
npm.cmd ci
npm.cmd start
```

1. `연결 및 설정`에서 각 도구의 홈 폴더를 확인합니다. 기본값은 사용자 홈의 `.claude`, `.codex`, `.gemini`이며, Claude와 Codex는 각각 `CLAUDE_CONFIG_DIR`, `CODEX_HOME` 환경변수도 반영합니다.
2. 필요한 도구의 `로컬 기록 수집`과 `기존 로그인으로 한도 조회`를 선택합니다. 설정은 선택 즉시 저장하며, 경로는 입력 후 포커스를 옮기거나 Enter를 누르면 저장합니다.
3. 최초 수집 후 로컬 기록은 기본 30초마다 확인합니다. 한도 갱신 주기는 연결별로 선택하며 기본값은 300초입니다.

인증이 만료되면 원래 CLI에서 다시 로그인한 뒤 갱신하세요. 앱 종료는 트레이 메뉴 또는 앱의 `앱 종료`를 사용합니다. 자동 시작과 위젯은 기본 꺼짐입니다.

## 실행 폴더 만들기

```powershell
npm.cmd run package
```

`dist/TokenTrailer/TokenTrailer.exe`를 실행합니다. **실행 파일뿐 아니라 생성된 폴더 전체가 필요합니다.** 설치 관리자와 관리자 권한은 필요하지 않습니다. 실행 폴더를 옮겼다면 자동 시작을 껐다 켜서 등록 경로를 갱신하세요. 생성한 패키지는 소스 저장소에 포함하지 않습니다.

## 데이터 처리

- 설정과 사용량 메타데이터는 Electron의 사용자별 `userData` 폴더에 저장합니다. 일반적으로 `%APPDATA%/TokenTrailer`입니다.
- 로컬 원본 기록을 읽어 토큰 수·시각·모델·프로젝트·세션 등 필요한 메타데이터를 추출합니다. 대화 원문과 인증 토큰은 앱 이력에 저장하지 않습니다.
- 한도 조회를 켜면 기존 인증 정보를 읽어 제공자의 고정 HTTPS API로 직접 요청합니다. 인증 파일을 수정하거나 인증 토큰을 자체 갱신하지 않습니다. 별도 수집 서버·텔레메트리·PC 간 동기화는 없습니다.
- 원본 기록이 삭제돼도 수집한 앱 이력은 남습니다. 앱에서 이력을 삭제하면 해시 식별자를 보존해 자동 재수입을 막으며, `과거 기록 재수입`에서 제외를 해제할 수 있습니다. 원본 기록은 변경하지 않습니다.
- 누락·갱신 실패·미확인 값은 사용량 0과 구분합니다. 작업표시줄의 `*`는 이전 성공값, `--`는 한도 미확인을 뜻합니다.

## 개발 검증

```powershell
npm.cmd test
npm.cmd run smoke
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/native-check.ps1
```

- `test`: 파서, 누적값 차분, 중복 방지, 집계, 설정, 한도 응답·오류 처리, 표시 형식을 합성 데이터로 검사합니다.
- `smoke`: 별도 프로필과 합성 데이터로 실제 Electron 화면·설정 저장·위젯 등을 검사합니다. 실제 인증·API를 사용하지 않습니다.
- `native-check`: 현재 작업표시줄에 잠시 시험 숫자를 표시하고 보조 창 복구를 확인합니다. Explorer를 종료하지 않습니다.

별도 스크립트 `node scripts/validate-local.mjs`는 현재 사용자의 실제 Claude/Codex 기록을 읽습니다. `--quota`를 명시하면 기존 인증으로 실제 한도 API도 조회합니다. 결과는 카운트와 상태만 출력합니다.

2026-10-25 공개 준비 시 `npm.cmd test` **22개가 모두 통과**했습니다. 이번 준비 과정에서는 UI·네이티브·패키징·실계정 검증을 재실행하지 않았습니다. 과거 실행 검증과 그 한계는 아래 보고서를 참고하세요.

## 현재 한계

- Gemini 실계정, 실제 로그인·Explorer 재시작·절전 복귀, 배율·다중 모니터·작업표시줄 자동 숨김 조합은 추가 검증이 필요합니다.
- 작업표시줄 직접 표시는 주 작업표시줄에 한정합니다. 비공식 Windows 셸 통합이므로 Windows 업데이트의 영향을 받을 수 있고, 빈 공간이 부족하면 표시하지 못할 수 있습니다.
- Codex는 누적 사용량의 차분을 집계하고 부모 기록과 일치하는 분기 상속분을 제외합니다. 부모를 확인할 수 없는 분기는 미지원으로 남깁니다. 발생 시각이 미확인인 첫 누적값은 기간 그래프에서 제외합니다.
- JSONL 마지막 미완성 행은 다음 갱신까지 보류하며, 128MiB 초과 기록 파일은 지원하지 않습니다.
- 비용 환산, 여러 PC 동기화·귀속 비율, 개인별 귀속, 자동 작업 유형 분류, Kimi·Grok 지원, 코드 서명·자동 업데이트·설치 관리자는 현재 범위에 포함하지 않습니다.
